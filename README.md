# Цифровой механик

AI-агент для механика автопарка: берет результат акустической проверки двигателя из ML-сервиса «НейроДВС», объясняет его простыми словами, отвечает на вопросы строго по руководству на двигатель этой машины со ссылкой на страницу PDF и по подтверждению механика оформляет заявку на дефектовку в ТОиР.

Хакатон «ИИкузница», трек «Цифровой аватар», задача «AI-агент „Цифровой механик“ для диагностики ДВС коммерческого транспорта». Сделано в спринте 26–28.11.2026, автор – Павел Логачев.

**Стенд:** https://mechanic.logachev.net (для жюри открыт без входа, работает с телефона).

## Что умеет

- Парк из 50 машин заказчика, поиск по госномеру и гаражному номеру, история проверок и график оценки отклонения.
- Кнопка «Получить результат диагностики»: агент сам вызывает ML-сервис и выдает вердикт. Три исхода выглядят и обрабатываются по-разному:
  - **норма** – можно работать по данным этой проверки; если раньше было критичное отклонение без заявки, агент предупреждает, что «норма» его не закрывает;
  - **отклонение** – тип, уверенность рядом с порогом заявки 0,60, приоритет с основанием, что проверить и чем это грозит, со ссылками на страницы руководства;
  - **сбой записи** – никаких выводов о двигателе, просьба перезаписать, заявка запрещена.
- Вопросы в чате («какое давление масла на холостом?», «можно ли своим ходом на базу?») – ответ только по руководствам двигателя этой машины, каждая цифра со ссылкой `[1]`, по клику открывается страница PDF с цитатой.
- Вопрос голосом прямо с карточки машины («что с машиной?» показывает результат проверки). Ответ текстом на русском, узбекском, таджикском, кыргызском, казахском или хинди; цитаты из руководства остаются русскими. Перед первой записью – согласие на обработку данных.
- Режим «Коротко | Подробно»: опытному – только суть, начинающему – каждый шаг простыми словами.
- Сомнительный сигнал (помехи в записи или уверенность ниже порога 0,60): предупреждение видно всегда, перезапись не нужна, агент отправляет осмотреть узел, заявку можно отправить только с отметкой «признак подтвержден осмотром».
- Нет инструкции по узлу в руководстве этого двигателя (или ML назвал класс, которого у двигателя быть не может): заявку продукт не отправляет, механик видит почему и получает готовый текст рекомендации на дефектовку с результатом проверки – кнопка «Скопировать текст».
- Заявка на дефектовку: агент собирает черновик (диагноз, приоритет, работы, запчасти, ссылки), механик правит и подтверждает кнопкой – только тогда заявка уходит в ТОиР и возвращается `ticket_id`.
- Дополнительно: память по машине (прошлые проверки и заявки), график `anomaly_score`, режим «Главный механик» со сводкой парка (норма / требует внимания / карантин).

## Как устроено

```
Телефон механика ──HTTPS──> FastAPI (app/main.py) ──> агент (app/agent.py) ──> LLM (DeepSeek, OpenAI-совместимый API)
                                   │                        │ инструменты:
                                   │                        ├─ get_diagnosis ──> Mock ML /diagnose (URL из .env)
                                   │                        ├─ search_manual / read_page ──> индекс руководств (app/search.py)
                                   │                        ├─ get_vehicle_history, get_fault_reference
                                   │                        └─ prepare_ticket (только черновик)
                                   └─ POST /api/tickets/confirm (кнопка механика) ──> Mock ТОиР /tickets
```

Принцип: **агент ищет и объясняет, программа проверяет, механик подтверждает.**

- **Агент** – свой цикл на tool calling, без фреймворков. Модель сама выбирает инструменты по контексту, сценарий не зашит в if-else (F5). Шаги агента видны в интерфейсе («Как помощник искал ответ»).
- **Приоритет считает код** (`app/priority.py`, политика PRIO-2), а не модель. Базовая тяжесть класса F01–F14 (критичный – давление масла, перегрев; значимый; легкий) плюс ограниченная поправка: оценка и уверенность, качество записи, повторы и рост по истории. Смысл приоритетов – как у заказчика: high – дефектовка до выпуска в рейс, medium – на ближайшем ТО под наблюдением, low – узел проверяется на следующей проверке. Это рекомендации: запрет эксплуатации агент пишет, только если он прямо есть в руководстве на этот двигатель, со ссылкой на страницу. Модель только объясняет результат.
- **Применимость к двигателю** (`app/faults.py`): если ML вернул класс, которого у этого двигателя быть не может (цепь ГРМ у ЯМЗ-236 с шестеренным приводом, зажигание у дизеля, турбина у ЗМЗ), агент не выдает это за диагноз, а предлагает очный осмотр и текст рекомендации на дефектовку, заявку не отправляет. В тестовых данных заказчика таких проверок 7.
- **Проверка ответа** (`app/verify.py`): ссылки только на руководства двигателя этой машины и только на страницы, которые агент реально открыл; каждое число из предложения со ссылкой ищется на этой странице. Если что-то не сходится, агент получает замечание и переписывает ответ; если и со второй попытки не подтвердилось – ответ помечается.
- **Поиск** (`app/ingest.py`, `app/search.py`): 6 PDF разобраны постранично (1743 страницы), 302 страницы с таблицами-картинками распознаны DeepSeek vision; гибридный поиск BM25 + эмбеддинги `multilingual-e5-small` (RRF), фильтр по двигателю до ранжирования, затем переранжирование 100 кандидатов моделью Jev. При недоступности Jev поиск продолжает работать без него.
- **Заявка** уходит в ТОиР только через `POST /api/tickets/confirm` по кнопке. Черновик собирается, только если среди ссылок есть страница руководства этого двигателя с проверкой, регулировкой или ремонтом именно узла из типа неисправности – оглавление и чужой узел не подходят (`app/faults.py`, `page_covers_unit`). Код еще раз проверяет поля; при норме и сбое записи заявку создать нельзя.
- **Факт и гипотеза раздельно.** Числа и порядок работ – только из руководства со ссылкой; возможные причины и риски помечены «вероятно» и не оформляются цитатой.
- **Противоречия руководств.** Если страницы расходятся, агент показывает обе формулировки со ссылками, называет противоречие и советует уточнить у специалиста. Подтвержденные заказчиком случаи (зазоры клапанов ЯМЗ-236: РЭ стр. 31 против РК стр. 269, 276) – в `app/conflicts.py` вместе с принятым консервативным правилом.
- URL ML-сервиса и ТОиР, модель и ключи – в `.env` (F6), рабочие сервисы подставляются без правки кода.

## Запуск за 5 минут

Нужны Docker и ключ DeepSeek (или любой OpenAI-совместимой модели).

```bash
git clone https://github.com/pavel-logachev/digital-mechanic && cd digital-mechanic
cp .env.example .env          # впишите LLM_API_KEY; OPENROUTER_API_KEY – по желанию (Jev)
python -m tools.fetch_manuals # 6 PDF с Яндекс Диска заказчика в data/manuals/ (или положите вручную)
docker compose build
docker compose run --rm app python -m app.ingest   # индекс руководств, ~2–5 мин; OCR ~$0,16 один раз
docker compose up -d
```

PDF руководств, индекс и тексты страниц в репозиторий не входят (авторские права, требование организаторов): база знаний подключается через `.env` – `MANUALS_DIR`, `INDEX_DIR`, `PAGES_DIR`, `EVAL_DATA_DIR`. На стенде она лежит в закрытом каталоге сервера.

Откройте http://127.0.0.1:8000. Заглушки ML и ТОиР заказчика (`mocks/`, без изменений) поднимаются в том же compose.

Без Docker: Python 3.12, `pip install -r requirements.txt`, заглушки – `uvicorn mock_ml.app:app --port 8001` и `uvicorn mock_toir.app:app --port 8002` из папки `mocks`, приложение – `uvicorn app.main:app --port 8000`.

Тесты: `pytest -q` (73 теста, гоняются в GitHub Actions на каждый push; интерфейс – `python web/check_ui.py`, 13 сценариев в браузере на телефонном экране). Оценка поиска: `python -m eval.retrieval_eval`. Сквозная оценка агента на контрольных вопросах: `python -m eval.agent_eval`.

## Работа в автопарке

Сервис готов к подключению в действующем парке: заглушки заменяются рабочими ML и ТОиР адресами в `.env`, код не меняется.

- **Учетные записи и роли.** `python -m tools.users add petrov "Петров П. П." mechanic` (или `chief`). Как только появилась первая учетка, сервис требует вход по логину и паролю. Механику не видна сводка парка, главному механику – видна. Пароли хранятся только хешем PBKDF2, сессия – подписанная cookie на 30 дней, после 10 неверных попыток вход с адреса закрывается на 15 минут. Отключить сотрудника: `python -m tools.users disable petrov`.
- **Журнал работы.** Каждый вопрос, ответ, ссылки на страницы, голосовой вопрос (только текст) и заявка с автором – в `STATE_DIR/audit/ГГГГ-ММ.jsonl`. Срок хранения – `AUDIT_RETENTION_DAYS` (180 дней), старые файлы удаляются сами. Звук не сохраняется нигде.
- **Сбои внешних сервисов.** Запрос в ML повторяется при сбое связи и ответах 5xx. Заявка в ТОиР повторяется только если соединение не установилось – когда ТОиР запрос точно не получил, чтобы не задвоить заявку. Двойное нажатие «Отправить заявку» создает одну заявку.
- **Резервная модель.** Если основная LLM не ответила после повторов, запрос уходит на резервную (`LLM_FALLBACK_MODEL`, по умолчанию Gemini 3.5 Flash Lite через OpenRouter: 24 из 25 на контрольном наборе против 25 из 25 у DeepSeek Flash). Если недоступен Jev, поиск работает без переранжирования.
- **Перезапуск без потерь.** Разговоры и черновики заявок сохраняются на диск после каждого ответа: после обновления или перезагрузки сервера механик продолжает с того же места.
- **Безопасность.** Заголовки CSP (только свои скрипты), запрет встраивания в чужие сайты, `nosniff`; ограничение частоты запросов к LLM с адреса и суммарно (`RATE_PER_IP_10MIN`, `RATE_GLOBAL_PER_HOUR`); контейнер работает не от root; руководства подключены только на чтение.
- **Новый двигатель.** Положите PDF в `MANUALS_DIR`, добавьте строку в `app/manuals.py` (двигатель, обозначение, год) и пересоберите индекс `python -m app.ingest`. Применимость классов F01–F14 к новому двигателю – в `app/faults.py`.
- **Мониторинг.** `/api/health` показывает доступность ML и ТОиР; healthcheck в Docker перезапускает упавший контейнер; в логе по каждому ответу время и расход токенов.

Экономика по разъяснению организаторов: сценарий – одна проверка машины от результата диагностики до ответа механику или заявки, все шаги модели внутри. В среднем по замерам он стоит **около 2,3 ₽**: объяснение результата ~0,24 ₽, 2,5 вопроса механика ~0,56 ₽ (DeepSeek), черновик заявки ~0,06 ₽ (в 46 % проверок), переранжирование Jev ~1,45 ₽, распознавание голоса ~0,03 ₽; эмбеддинги запроса считаются локально бесплатно (дневной тариф DeepSeek, курс ЦБ 82,31 ₽/$). Парк 50 машин с проверкой раз в две недели – около 109 проверок в месяц: модели ~250 ₽/мес, вместе с VPS ~1 750 ₽/мес, ~35 ₽ на машину. Разовая индексация руководств – ~13 ₽ отдельной строкой. Расчет по шаблону организаторов – [`docs/economics/cost-per-request.xlsx`](docs/economics/cost-per-request.xlsx).

Две ошибки из 72: в одном вопросе агент не нашел таблицу неисправностей цепи ГРМ и ответил неполно, в другом эталон сам ссылается на страницу о другом фильтре (вопрос спорный).

## Что не сделано

- Шаги 1–3 из описания бизнес-процессов (фото госномера с распознаванием, фото положения стенда, запись звука) – в прототипе машина и проверка выбираются из списка, как в обязательном минимуме ТЗ.
- Вход через корпоративные учетные записи парка (AD, 1С) не подключен: учетки ведутся в `users.json` командой `tools.users`.
- Таблицу критичности F01–F14 заказчик не задает: тяжесть классов и порог уверенности 0,60 – наша политика по смыслу классов и руководствам, схема «база + ограниченная поправка» заказчиком признана допустимой. Таблица в `app/faults.py`, правила в `app/priority.py`, меняются без правки логики.
- Каталожных номеров запчастей нет: запчасти указываются названиями из руководства.

## Сторонние компоненты и раскрытие

- Модели: DeepSeek `deepseek-flash` (агент и распознавание таблиц-картинок), `typesafe/jev-1.13` через OpenRouter (переранжирование страниц), `google/gemini-3.5-flash-lite` через OpenRouter (распознавание голосовых вопросов и резервная LLM), `intfloat/multilingual-e5-small` (эмбеддинги, локально).
- Библиотеки: FastAPI, Uvicorn, httpx, openai, PyMuPDF, rank-bm25, sentence-transformers, NumPy.
- Заглушки ML и ТОиР, данные парка и руководства – материалы заказчика ООО «НейроДВС» (`mocks/`, `data/manuals/`).
- До старта спринта (разрешено п. 4.4 Положения и ответами организаторов) подготовлены и использованы как знания, без переноса кода: анализ предметной области, макеты экранов, набор контрольных вопросов (хранится вне Git, см. `eval/README.md`), замеры вариантов поиска и OCR на публичных версиях руководств, пустой репозиторий и окружение.
- При разработке использовались ИИ-ассистенты программирования (Claude, Hermes Agent).
