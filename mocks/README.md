# НейроДВС: заглушки Mock ML и Mock ТОиР

Материалы для команд хакатона «ИИкузница» (26–27.11.2026), задача «Цифровой механик». Две заглушки по контракту из раздела 5 ТЗ версии 6 и синтетические данные по парку из 50 машин. Реальных записей и данных автопарков здесь нет.

## Состав

| Путь | Что это |
|---|---|
| `mock_ml/app.py` | Mock ML API, `POST /diagnose` |
| `mock_toir/app.py` | Mock ТОиР, `POST /tickets` |
| `data/vehicles.json` | 50 ТС, у каждого от 3 до 5 проверок, всего 195 проверок |
| `data/fault_types.json` | справочник типов неисправностей F01…F14 |
| `openapi_ml.json`, `openapi_toir.json` | спецификации OpenAPI |
| `tests/test_mocks.py` | тесты заглушек |
| `tools/export_openapi.py` | выгрузка спецификаций заново |
| `.env.example` | адреса сервисов для вашего приложения |

## Запуск

Нужен Python 3.10 или новее. Проверено на Python 3.14.4 и 3.11.9 в Windows 11; на Linux, macOS и Python 3.10 запуск не проверялся. Версии библиотек в `requirements.txt` закреплены.

```bash
python -m venv .venv
```

Windows, командная строка cmd:

```bash
.venv\Scripts\activate
```

В PowerShell активация может быть запрещена политикой выполнения скриптов. Тогда либо работать в cmd, либо сначала выполнить в этом окне:

```bash
Set-ExecutionPolicy -Scope Process Bypass
```

Linux и macOS:

```bash
source .venv/bin/activate
```

Дальше одинаково:

```bash
pip install -r requirements.txt
```

Сервисы запускаются в двух терминалах из корня папки, в каждом окружение активируется заново:

```bash
uvicorn mock_ml.app:app --port 8001
```

```bash
uvicorn mock_toir.app:app --port 8002
```

Интерактивная документация с формой запроса: `http://127.0.0.1:8001/docs` и `http://127.0.0.1:8002/docs`. Проверка, что сервис жив: `GET /health`.

Тесты:

```bash
pytest -q
```

Адреса сервисов в вашем приложении задаются переменными окружения, как требует F6 ТЗ. Образец в `.env.example`. Запросы из браузера с другого адреса разрешены (CORS открыт).

## Mock ML API

`POST /diagnose` принимает пару идентификаторов и возвращает результат проверки. Аудио не передаётся. Списка машин сервис не отдаёт: список ТС и история проверок читаются из `data/vehicles.json`.

```bash
curl -s -X POST http://127.0.0.1:8001/diagnose -H "Content-Type: application/json" -d "{\"vehicle_id\": \"M333YK47\", \"session_id\": \"S-0005\"}"
```

Примеры с `curl` написаны для cmd и bash. В PowerShell 5.1 `curl` — это другая команда, там удобнее форма на странице `/docs`.

```json
{
  "vehicle_id": "M333YK47",
  "session_id": "S-0005",
  "status": "anomaly",
  "anomaly_type": "F08",
  "anomaly_title": "Дизельная топливоподача",
  "anomaly_score": 0.76,
  "confidence": 0.73,
  "signal_quality": "good",
  "description": "Жёсткая работа с резким стуком в цилиндрах, дымный выхлоп",
  "model_version": "mock-v1"
}
```

| Поле | Значения |
|---|---|
| `status` | `normal`, `anomaly`, `check_failed` |
| `anomaly_type` | `F01`…`F14` или `null` |
| `anomaly_title` | название типа из `fault_types.json` или `null` |
| `anomaly_score` | число от 0 до 1 или `null`; при `anomaly` не меньше 0,5 |
| `confidence` | число от 0 до 1 или `null` |
| `signal_quality` | `good`; `warning` — запись с помехами, уверенность модели снижена; `bad` — запись непригодна |
| `description` | текст от модели |
| `model_version` | `mock-v1` |

При `status = normal` поля `anomaly_type` и `anomaly_title` равны `null`. При `status = check_failed` `null` также `anomaly_score` и `confidence`, а `signal_quality` равно `bad`.

Модели двигателя в ответе нет. Она указана в карточке ТС в `vehicles.json`, и по ней выбирается руководство.

Коды ответа: `200` — результат; `404` — неизвестный `vehicle_id` или `session_id`, либо проверка принадлежит другой машине; `422` — тело запроса не по схеме; `400` — тело не разобрано, чаще всего из-за кодировки (нужна UTF-8). Госномер пишется латиницей, регистр важен.

## Mock ТОиР

`POST /tickets` принимает заявку на дефектовку и возвращает её номер.

```bash
curl -s -X POST http://127.0.0.1:8002/tickets -H "Content-Type: application/json" -d "{\"vehicle_id\": \"M333YK47\", \"session_id\": \"S-0005\", \"anomaly_type\": \"F08\", \"conclusion\": \"conclusion text\", \"urgency\": \"medium\", \"operations\": [\"operation 1\"], \"spare_parts\": [], \"references\": [{\"manual\": \"manual name\", \"pdf_page\": 1}]}"
```

Текст в примере латиницей, чтобы команда работала в любой консоли. Русский текст в заявке допустим, тело должно уйти в UTF-8.

```json
{"ticket_id": "TKT-0001", "status": "created"}
```

| Поле | Требование |
|---|---|
| `vehicle_id`, `session_id` | существующая пара из `vehicles.json` |
| `anomaly_type` | значение `anomaly_type` из ответа `/diagnose`, `F01`…`F14` |
| `conclusion` | диагноз, непустая строка |
| `urgency` | приоритет, одно из значений `low`, `medium`, `high` |
| `operations` | работы, непустой список строк |
| `spare_parts` | запчасти, список строк, может быть пустым |
| `references` | ссылки на источники, непустой список объектов `{"manual": "...", "pdf_page": N}`; `manual` — обозначение или название документа, как в разделе 3 ТЗ, непустая строка; `pdf_page` — номер страницы PDF, от 1 |

Коды ответа: `201` — заявка создана; `404` — неизвестная машина или проверка; `422` — заявка не по схеме; `400` — тело не разобрано.

Заглушка проверяет схему заявки и существование пары машина — проверка. Смысл заявки она не проверяет: совпадение `anomaly_type` с результатом проверки, уместность заявки при `normal` и `check_failed`, работы и страницы остаются на вашей стороне.

Заявки хранятся в памяти процесса, после перезапуска нумерация начинается с `TKT-0001`. Списка заявок сервис не отдаёт: историю заявок по машине приложение ведёт само.

Карточка ТС: `vehicle_id` — госномер, `garage_no` — гаражный номер, `make` — марка, `model` — модель (у МАЗ с ЯМЗ-536 равно `null`), `vehicle_type` — тип машины, `engine_model` — модель двигателя, `fuel` — топливо.

Проверки внутри машины идут по времени, от ранней к поздней. Запись проверки в файле совпадает с ответом `/diagnose` на эту пару идентификаторов, плюс поле `checked_at`.

## Ограничения

- Все данные синтетические, описания звука в поле `description` написаны для заглушки.
- Заглушка ML ничего не вычисляет: она отдаёт заранее записанный результат.
- Руководств по двигателям в этой папке нет, они выдаются отдельно.
